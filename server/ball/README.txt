Билеты на предновогодний бал — REG.RU, PHP 8.2 / MySQL 8

Содержимое
- public/api/ball.php: config/create/pay/status/webhook.
- public/api/ball-lib.php: серверная логика, фиксированные цены 35000/50000 RUB.
- public/api/ball-admin.php: кабинет организатора, друзья, регистрации, CSV.
- public/setup-ball.php: только CLI; при HTTP-запросе отдаёт 404.
- Конфигурация: /var/www/u3713220/data/.otrazis-ball/config.json (ВНЕ www).
  Права папки 0700, файла 0600. Конфигурация не входит в Git или архив сайта.
- ball_orders/ball_codes: новые таблицы, не изменяют и не восстанавливают старую базу Supabase.

Установка (сайт и MySQL уже созданы)
1. Загрузить архив в www/отразись.рф, сохранить текущую папку в резервную копию,
   распаковать архив с заменой. Сборка содержит только новые/изменённые файлы
   относительно установленного полного архива 6 ноября; не удалять старые assets.
2. В Shell перейти в папку сайта и выполнить: php setup-ball.php setup
   Ввести имя базы и пользователя u3713220_otrazis (сверить в панели), пароль,
   Shop ID 1495081, секретный ключ и отдельный пароль кабинета организатора.
   Пароли вводятся скрыто, не помещаются в историю команд.
   Если чеки ещё не проверены — выбрать notready. Продажи будут закрыты.
3. Убедиться в панели сайта, что веб-версия PHP тоже 8.2 или новее с PDO MySQL/cURL.
4. Проверить: php setup-ball.php check
   Проверка ключа только читает список платежей, не создаёт платёж и не списывает деньги.
5. В кабинете ЮKassa / Интеграция / HTTP-уведомления установить URL:
   https://xn--80aodvkjc9f.xn--p1ai/api/ball.php?action=webhook
   События: payment.succeeded, payment.canceled, refund.succeeded.
   Вебхук перепроверяет объект через API с ключом магазина, сумму, валюту,
   metadata заказа, получателя, test и paid. Повторные уведомления безопасны.
6. Выдача чеков: выбирать yookassa только при подключённой кассе/сервисе чеков.
   НДС, СНО и признак расчёта для билетов должны соответствовать настройке кассы.
   Режим external допускается только при уже настроенной внешней фискализации.
   Сам пакет external-чеки не отправляет. Старый режим пожертвований не перенесён.
7. Проверить на тестовом магазине ЮKassa (его отдельные Shop ID/секрет и test_mode=yes):
   билеты обоих типов, успешную/отменённую оплату, возврат, повторное уведомление,
   код друга и повторное применение кода. Затем setup с боевыми данными.
   Тестовые заказы и коды сохраняют флаг TEST, не превращаются в боевые.
8. Для открытия после проверки: php setup-ball.php enable
   Подтверждение OPEN открывает выбранный режим магазина. Реальная контрольная
   оплата производится владельцем магазина; автоматические тесты денег не списывают.
   Для остановки: php setup-ball.php disable

Кабинет организатора
https://xn--80aodvkjc9f.xn--p1ai/api/ball-admin.php
Вход по паролю из setup. Сессия 30 минут, Secure/HttpOnly/SameSite, CSRF-защита.
Создание 1–100 индивидуальных DRUG-кодов за раз. Каждый код — один бесплатный
заказ любого типа. Код показывается полностью только при создании: сохранить
перед обновлением страницы. Список показывает суффикс, статус и число гостей.
Отключить можно только неиспользованный код. Уже оформленные гости не отменяются.
Статусы: paid/free — подтверждены; pending — ждёт оплаты; canceled — отменён;
refunded — был возврат, билет требует проверки организатором.
CSV содержит все регистрации, оплаченные/друзья первыми, новые выше, тестовые
помечены. На экране последние 500. Встроенной почтовой рассылки пока нет:
подтверждение с номером доступно посетителю на сайте и скачивается как TXT.
Администратор видит имя, второго гостя, контакты, сумму, статус, ЮKassa ID в CSV.

Зачёт билета
35 000 рублей для single, все 50 000 для pair. Друзья оплачивают 0 и имеют
нулевую сумму к зачёту. Фактический зачёт производится организатором при
расчёте за лот; автоматической оплаты лотов этот пакет не реализует.

Сверка и эксплуатация
php /var/www/u3713220/data/www/xn--80aodvkjc9f.xn--p1ai/setup-ball.php reconcile
Можно назначить каждые 5 минут в CRON панели. Проверяет до 100 известных
платежей за запуск (самые давно проверенные первыми), восстанавливает ID платежей
при потере ответа на создание. Сохранять вывод в приватный лог, не в www.
Резервное копирование MySQL и приватной папки настроить средствами хостинга.
Повторная setup сохраняет app_key и записи, но закрывает продажи для проверки.
Секретный ключ не передавать в переписке, не добавлять в Git или браузерный код.

Проверки
26 серверных сценариев: цены, один/два гостя, код, транзакционный повтор/гонка,
сумма/магазин/валюта/metadata/test/paid, дубликат webhook, статус назад, возврат,
50000 зачёта, чек, потерянный ответ и идемпотентность <24ч, токен доступа.
SQLite и отдельный MySQL 8; браузерные сценарии PHP + Vite на 320/390/1440px.
В браузерном тесте внешний платёж не создавался; сетевой сбой имитирован.
Перед боевым запуском остаются проверка магазина владельцем и настройка чеков.
